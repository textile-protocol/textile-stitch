# ERC-8004 agent identity

Optional. A Stitch bot can register itself in the public [ERC-8004](https://eips.ethereum.org/EIPS/eip-8004) agent registry on its own chain, so other agents can find it and, over time, build up a track record for it. Quoting doesn't change either way.

Registering is one transaction from the operator wallet: `register(agentURI)` on the chain's Identity Registry. That mints an ERC-721 to the operator wallet, and the registry records the same address as the agent's wallet. The registration file (name, description, services) is stored onchain inside the agentURI as a base64 `data:` URI, so nothing is hosted anywhere and only the owner can change it.

## In the panel

Bot → Tools → **ERC-8004 agent identity**. The name and description start from generated text (the bot's name plus its pair, and a one-line description) and you can edit both before registering. **What gets stored onchain** shows the exact file. Register asks once, sends the transaction, and records the agent id in `stitch.toml`.

The same rules as Approve allowances apply: a bot with its taker or closer leg on has to be stopped first, because the mint takes a nonce from the same wallet. A Fireblocks bot without raw signing sends the mint as a Contract Call, the same way its approvals go out, so the Fireblocks policy needs a Contract Call rule for the registry address. If the call waits on a co-signer longer than the panel waits, the card shows it as pending, and **Check again** asks Fireblocks about that same call. It never sends a second one while the first can still land, from this bot or any other bot on the same wallet. The pending call is kept under the bots folder in `.erc8004-pending/<chain>-<wallet>.json`, one file per chain and wallet, so it still applies if the bot that started it is moved to another wallet. It's written before the call is sent, with the `externalTxId` it's sent under. If Fireblocks' response gets lost, the panel finds the call again by that id, and Fireblocks refuses a second call with it. Linking the identity by id clears the file; if a call is stuck and you've cancelled it in Fireblocks, the next check clears it too.

If the wallet already owns an identity, for example one registered by hand or by another bot on the same wallet, the card offers to link it by id instead of minting a second one. The panel checks `ownerOf` before saving it.

## On the CLI

```bash
stitch register --config stitch.toml --dry-run      # print the file and the cost, send nothing
stitch register --config stitch.toml \
  --name "Acme MM · cNGN/USDT" \
  --description "Market-making bot quoting cNGN/USDT on Textile FX (Celo), running Stitch."
stitch register --config stitch.toml --agent-id 1847  # link one the wallet already owns
```

Without `--name` and `--description` it uses the generated text. It writes this to the config:

```toml
[erc8004]
agent_id = 1847
```

Rerunning is safe. A config that already has an agent id sends nothing, a wallet that already owns an identity is refused a second mint and pointed at `--agent-id`, and a wallet with a transaction still waiting in the pool is refused until it lands, so a rerun after a timed-out mint can't queue a second one. The last line of output is `agent_id=<id>`.

## Chains

| Network | Identity Registry |
|---|---|
| Ethereum, Optimism, BNB Smart Chain, Polygon, Robinhood Chain, Base, Arbitrum, Celo | `0x8004A169FB4a3325136EB29fA0ceB6D2e539a432` |
| BNB Smart Chain testnet, Base Sepolia, Arbitrum Sepolia, Celo Sepolia, Ethereum Sepolia | `0x8004A818BFB912233c491871b3d84c89A494BD9e` |

On any other chain the card says there's no registry and `stitch register` exits without sending.

## Cost

Storing the file onchain is the expensive part: about 460k gas for the default text. That's around 0.09 CELO on Celo and a fraction of a cent on Base or BNB Smart Chain at typical gas prices. The panel shows the estimate and the wallet's balance before you register, and wants a little headroom over the estimate in case the fee has to be raised.

## What the operator wallet owning it means

The identity belongs to the key that signed the mint. That key can change the stored file (`setAgentURI`) or transfer the identity. Removing the bot deletes the key, and the identity stays registered with nobody able to change it.

A vault maker's trades settle from its OperatorVault, not the operator wallet. The vault can't be made the agent's wallet: the registry needs a signature from the new wallet, and the vault only signs order envelopes. So the vault is listed in the file as a `wallet` service instead.
